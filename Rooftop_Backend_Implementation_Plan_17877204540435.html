Solar Site Fitness & Capacity Engine — Rooftop Scope

Backend Implementation Plan

Python/FastAPI · Rooftop-only (floating/water-body work on hold) · Four-person parallel build, sized to equal effort

Rooftop-Only Requirement Scope

In scope: SITE-01..07, GEO-01,02,04,05,06,07,08,09 (drop GEO-03), AREA-01..06, CON-01,02,03,04,05,07,08,09 (drop CON-06), CAP-01..06, GEN-01..06, FIT-01..07, API-01..09, CAL-01..05, CFG-01..05, VIS-01..06, VIZ-01..05, ML-01..05, CACHE-01..05, USN-01..06, OBS-01..09 v1.2, SHADE-01..05 v1.2.

Dropped for now: GEO-03 (WATER_INDEX/Sentinel-2), CON-06 (floating pack), the entire §13 Sentinel-2 pipeline, and the floating-specific row in the §16 testing table.

New in v1.2 — §9.16 Obstacle Detection & §9.17 Shading Analysis Obstacle detection (OBS) reuses VIS-01's crop and VIS-02's vision-LLM call — same image, same request, extended structured-output schema — and is the one stage in the pipeline that auto-applies to a customer-visible number: a detection at/above a confidence threshold auto-unions into exclusions and recomputes usable area, versioned and reversible via the same SITE-05 mechanism as any other boundary change (never silent, unlike every other v1.1 addition's advisory-only discipline). Shading analysis (SHADE) extracts sunshine/shading data already present in the Solar API response Person 1 fetches for GEO-04 — no new external call — and threads it through as a generation derate (Person 2) and a fitness sub-score (Person 4).

3AI Pipeline & Cache
Covers, per the document §9.11 Vision Refinement (VIS-01..06) — "crop the source imagery to the provider-derived boundary... send the crop to a vision-LLM for a refinement pass... inference-time only, explicitly no fine-tuning." §9.12 3D Visualization (VIZ-01..05) — "generate a 3D panoramic model of the site... from the confirmed boundary plus available elevation/imagery data." §9.14 Result Cache (CACHE-01..05) — "a site already analysed at a given location... is never re-processed," keyed on rounded lat/long, cache hits always recorded as such. New in v1.2: §9.16 Obstacle Detection (OBS-01..09) — folds into the same vision-LLM call as VIS-02 (never a second crop, never a second call), but is the one stage in the whole pipeline that auto-applies to a customer-visible number: a detection at/above the configured confidence threshold auto-unions into exclusions and triggers AREA-04 recomputation, versioned via SITE-05 and independently reversible — never silent, unlike everything else this person owns.
  1. Confirm the Day-0 Celery/Redis skeleton runs a real task end to end.
  2. Alembic migration: site_analysis_cache table per §14 (lat_rounded, lng_rounded, boundary, vision_refinement jsonb, weather_snapshot jsonb, panorama_url, ml_suitability_score, ml_model_version, created_at, last_reused_at), unique index on (lat_rounded, lng_rounded) (CACHE-01).

  5. get_or_create_analysis() cache-miss path — trigger the full pipeline once, store the result, same table/key regardless of site type (CACHE-03).
  6. Admin "force refresh" endpoint bypassing the cache for a known-stale entry, never automatic (CACHE-04).
  7. providers/vision.py — crop source imagery to the boundary before any downstream use. Day 2 decision: imagery is the real Google Solar API Data Layers rgbUrl (a georeferenced GeoTIFF), not a plain map screenshot — cropping uses the image's own embedded geotransform via rasterio/GDAL, which also sets up VIZ-01's elevation source (dsmUrl) to reuse the same fetch machinery (VIS-01) done.

  13. engine/obstacles.py — below-threshold obstacles stay advisory-only, same discipline as VIS-03 (Obstacle.applied stays False) (OBS-05) v1.2.
  14. engine/obstacles.py — admin-reject path for an auto-applied obstacle: supersede the exclusion (SITE-05 history retained, never deleted), recompute usable area back (OBS-06) v1.2.

Integration Checkpoints

  • Checkpoint 1: synchronous, rules-only rooftop assessment end-to-end — address in, Solar-API boundary out, usable area computed, constraints resolved, capacity + generation estimated (shading-derated when available), deterministic FIT verdict returned (shading sub-score included). Requires Persons 1, 2, and 4's FIT+API-01..05 (no VIS/VIZ/ML/CACHE/USN/OBS yet).
  • Checkpoint 2: the same flow now runs through VIS refinement, produces a VIZ panorama, checks/writes the CACHE, adds the additive ML score, and captures USN for billing-linked types. A second request at the same rounded lat/long returns instantly with cache_hit=true and zero external calls.
  • Checkpoint 3 v1.2: the same VIS call now also returns obstacles; a high-confidence one auto-applies to exclusions (new SITE-05 version, source="obstacle_detection") and AREA-04/usable area recompute automatically; an admin can reject it and the site's usable area returns to its prior value with full history retained. A low-confidence obstacle stays advisory-only, visible but unapplied.
